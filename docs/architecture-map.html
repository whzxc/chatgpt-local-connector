01 / RUNTIME

三个入口，一个共享 Core

桌面应用和本地插件可以独立使用。只有使用相同数据目录、相同原生构建的本地客户端，才会连接到同一个 Core。

选择节点查看实现细节

图中展示主流程；点击节点可查看对应源码、边界说明与开发命令。

生命周期最后一个本地租约关闭后，Core 回收；外部 Desktop 任务保留其原所有权。

运行依赖主安装包与插件不需要 Node/npm。某些可选 Agent 适配器有独立运行时和安装条件。

箭头表示请求分派与执行关系。回执、鉴权上下文和结果存储是共享能力；AgentHost 与 Control 不复制各自的上游运行时。

03 / DEVELOPMENT

桌面应用的开发流程

主入口是 npm run dev。桌面 React 热更新、Tauri 壳重启、独立 Core 重编译是三种不同的更新边界。

选择节点查看实现细节

图中展示主流程；点击节点可查看对应源码、边界说明与开发命令。

共享数据桌面开发默认复用安装版数据；插件开发默认使用独立的 -dev 数据目录。

开发前提Node 24.12+、npm、Rust stable 与平台 SDK；macOS 桌面图标构建需要 Xcode。

04 / DEVELOPMENT

本地插件：保存 → 重建 → 自动刷新

通过现有 MCP 通道更新自包含 HTML。无需本机 HTTP 服务、HTTPS 证书或 CDP 参与日常开发；这条链路会重置面板临时 UI 状态。

缓存边界资源 URI 包含编译资源指纹；开发运行时再用 revision 比较新的 HTML。

发行边界自动轮询与 blob 重载仅用于开发；发行包没有开发目录、外部脚本和开发服务依赖。

05 / DEVELOPMENT

Core 各业务模块的开发闭环

不同模块共用一条原生编译链，但验证终点不同。修改 Core 之后，应重启开发命令重建独立可执行文件；仅重启 Tauri 壳不够。

选择节点查看实现细节

图中展示主流程；点击节点可查看对应源码、边界说明与开发命令。

检查入口npm run check:format / check / test / check:native 分别覆盖格式、前端类型、既有契约和原生编译。

构建归属这些 Rust 业务模块最终进入同一 local-connector 可执行文件，不分别产生独立安装包。

07 / BUILD

一份原生能力，两类可安装产物

独立插件可以单独构建；桌面构建会使用同批 Core 二进制，再生成匹配的平台插件 ZIP。npm run build 只准备前端和原生开发产物，不生成安装包。
