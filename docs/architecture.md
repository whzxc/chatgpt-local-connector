# Architecture

Vue + Tauri + Rust provides a single native core for connection state, MCP requests, idempotent receipts, and user logs. The frontend runs in the system WebView; the main application package includes no Node/npm/node_modules. Claude ACP components and a private Bun runtime are downloaded into the application data directory on explicit enable; they reuse the installed Claude executable and run only as task-owned children.

`service::Service` owns the only Control and AgentHost, and a map of `ingress::Ingress` runtimes. Each ingress owns its lifecycle lock, listener, provider child, temporary directory, URL, logs, error and verification challenge. Runtime failure or stop affects only that ingress. Core shutdown closes all ingresses, then AgentHost and Control. Desktop-owned Codex tasks retain Desktop ownership.

Control source (a client label), transport, and authentication are independent. OpenAI Secure Tunnel uses its official identity; its stdio adapter forwards to the desktop local `/mcp/<ingressId>` endpoint with the private management credential. HTTPS listeners expose only `/mcp`, never the management API. Every listener captures its ingress at creation; requests cannot select another ingress with headers or arguments. All listeners enter the same MCP dispatcher and shared execution core. A separate listener per ingress keeps provider routing and authentication explicit without cloning the execution core. Cloudflare Quick, ngrok, Pinggy, and LocalXpose use ephemeral loopback ports; Cloudflare Fixed uses its configured loopback port, matching the remote route. Custom Domain uses a configured listening address/port. Duplicate bound ports fail explicitly.

HTTPS supports `none`, independent `bearer` credentials and OAuth with PKCE, DCR/preregistration and local owner consent. Invalid credentials return 401 without details. Protected local secret files are separate from ordinary configuration; status and logs do not expose secrets. Tool policies are `all` or an allowlist and apply to both discovery and invocation. The tool registry also owns editor groups, preset membership and required readers. The authenticated local `GET /api/tool-catalog` returns the full inventory independently of ingress policy; the editor expands restricted selections into explicit allowlists. They do not provide task/user isolation: every allowed task tool sees the shared namespace. Slack identity and per-user RBAC are not implemented.

The dispatcher scopes a task-local origin containing ingressId, controlSource and authType. It records this context in new operation receipts and Agent tasks, propagating it explicitly to background operations. A label is not an authenticated person; bearer proves possession only. Existing tool schemas do not require an origin argument. Wait request cancellation is scoped to an ingress; within one stateless ingress, simultaneous wait IDs must be unique.

`ingresses/index.json` identifies persisted entries. Each entry has its own config, protected secrets, verification and logs. On first load, a 0.6.x single connection becomes `default` with `toolPolicy=all`; HTTPS remains unauthenticated and OpenAI keeps its identity. After successful migration the legacy connection/verification files are removed. The UI's primary-connection fields are a projection of the default ingress (or first remaining ingress), not a second persisted model. The global summary reports running/ready/total independently of individual errors.

Codex Desktop owns tasks by default. Disabling Automatically open Codex tasks assigns new tasks to Connector's app-server. Ownership is persisted; toggling the setting does not move existing tasks. Ingress start does not require a Codex session: drivers initialize on demand. Read, send and wait through another ingress retain original task ownership.

The 42 tool definitions in `native/src/catalog.json` are embedded in Rust builds. JSON Schema validates parameters, and writes have persistent receipts. Large outputs support pagination. Persistent events are separate from UI logs, which omit routine protocol handshake noise.

Desktop access has no app-version allowlist; actual protocol and task ownership checks determine compatibility. External task management supports macOS and Windows. See [desktop lifecycle](desktop.md) and [MCP tools](tools.md).

Task approval is an optional confirmation flow controlled locally or from the cloud. Request content, approval decisions, and submission state share persistent receipts. Tasks groups requests by threadId and reads native runtime snapshots without parsing conversation JSONL. Approval settings persist independently, can change while connected, and do not change Codex execution permissions.

`native/src/waiter.rs` provides a shared read-only waiting engine. The Codex adapter stays attached to the task's App Server or Desktop owner. Notifications wake the waiter; fresh native snapshots determine state, with a two-second fallback check. Truncated buffers, missing notifications, and coalesced events do not affect the final classification. Reads and waits do not hold a global lock. Cancelling drops the wait future without interrupting the turn. Connector shutdown notifies waiters through a watch channel.

## Agent boundaries

The shared dispatcher sends `agent_*` routes to `AgentHost`; existing `codex_*` routes still go directly to `Control`. The Host owns common task identity, persistent receipts, confirmation, and lifecycle. `AgentDriver::CodexNative` adapts shared arguments/results while reusing Control; it preserves Desktop ownership, schema, events, account, plugin, and skills semantics.

`agents/builtins.json` and user manifests share a strict Manifest type for launch arguments, discovery, version probing, and compatibility. Static descriptions do not claim negotiated capabilities. `AgentDriver::Acp` shares descriptor-driven discovery/startup and negotiates ACP v1; `AgentDriver::Pi` uses official RPC. They share bounded JSONL transport while handling responses and completion separately. Each task has its own process; raw sessions and CLC identities persist separately. Restarting a process never automatically replays unknown writes. See [Local Agents](agents.md) for capabilities and limits.

`agent_wait` and `codex_wait` expose resumable bounded event-driven long polls (30-second default, explicit maximum 300 seconds). Clients should use 20–30-second slices, retaining the same task/thread and turn IDs and passing each snapshotHash as expectedHash after timeout; timeout never stops or recreates the task. ChatGPT, Notion, Slack and other MCP clients can have different outer tool-call deadlines; no per-client timeout configuration is required. Both tools share waiter timeouts, event wakeups, periodic checks, snapshot hashes, and condition evaluation. Codex delegates to its native wait entry point. Pi/ACP use a lightweight `WaitSource` over existing Host/Driver process observations without starting or resuming tasks. Pi checks `get_state`; ACP uses live process protocol state and the final prompt response. Waiting holds no global lock. MCP cancellation and disconnect release only the current wait.


Project facts support an explicit Review view with canonical workspace paths, shared sensitive-path filtering and best-effort observation metadata. It does not change host permissions or provide user isolation. `agent_context` is an on-demand projection over Control/AgentHost and current Git facts; it owns no tasks or persistent semantic state. Evidence, claims and missing coverage remain distinct. Shared diagnostic projections derive scoped findings from existing ingress/Core observations and perform no repair actions.
