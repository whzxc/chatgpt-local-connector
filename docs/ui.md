# UI components

The Vue desktop frontend uses Naive UI for standard controls. Import components by name rather than registering the entire library. `UiProvider` owns shared typography, control sizes, corner radii, brand colors, dark mode, and the English/Chinese component locale. `theme.ts` owns reactive appearance and theme-color preferences. General settings place five circular color swatches immediately below Appearance: Forest (default), Ocean, Violet, Amber, and Rose. The locally persisted selection updates control accents and the canvas in both light and dark modes. Translucent is a separate, locally persisted switch below the theme colors, disabled by default. It reveals native macOS Sidebar through a neutral translucent canvas (white in light mode, black in dark mode), without tinting the background with the theme color. Windows uses one native Acrylic backdrop behind both the content and caption buttons. Turning Translucent off restores an opaque canvas. Panels remain opaque for readability. Browser previews show the translucent styling but cannot blur the desktop behind the browser.

## Forms and panels

- Use `NForm` and `NFormItem`, with labels above inputs and one column by default. Listener addresses and ports are managed by the application; show a copyable reverse-proxy target when needed, not editable fields.
- Use `NInput`, `NInputNumber`, `SingleChoice`, `NSwitch`, and `NButton` for standard controls. Supply accessible input names.
- Put credential and provider help links on the right of the field label, on the same line. Show the selected platform in the dialog title; the editable display name remains a form field. Platform selection uses the bundled brand icons, with a dashed plus for custom sources.
- All single-choice fields use `SingleChoice`: up to five options render as capsule tabs when they fit the available width; more than five options or insufficient width use a dropdown, except the theme-color selector, which uses five circular swatches. Radio colors and capsule radii belong to `UiProvider`. Preserve accessible labels, keyboard navigation, disabled states, and form validation.
- Alerts and banners omit leading icons. ChatGPT shows a Secure Tunnel recommendation tag with a hover explanation instead of a preset banner. HTTPS-only sources omit the transport selector and include HTTPS MCP in the provider label.
- The final connection field is Tool list (工具列表): All / Common / Read-only / Custom. The field stays compact in every mode, showing a tool count and View all. A nested ElasticPanel lists preset tools or provides grouped Naive UI checkboxes for Custom, with Done/Cancel staging selection in the connection form; required verification and reader dependencies remain selected. The authenticated management catalog is independent of ingress discovery filters.
- Keep validation next to its field. Connection dialogs render every applicable field directly, without collapsed sections. Errors do not submit or close the form.
- Use `ElasticPanel` for control-source configuration, connection details, Agents, tool lists, task details, and application updates. Panels expand from the clicked trigger toward the window center, with content-driven height, viewport-constrained maximum dimensions, scrollable content, and an optional footer. The shared panel has no width toggle. Its `headerless` mode removes the title bar and close button while preserving equal outer padding; Agent quota details use this mode. Width and content-driven height changes transition smoothly over 320ms while preserving window-centered positioning; reduced-motion preferences disable this transition. Clicking outside or pressing Escape closes only the topmost panel with the collapse transition and restores focus to its trigger. Parent panels and workspace controls remain inert until the topmost panel finishes closing. Layered shadows distinguish the active panel; covered panels use softer shadows. Panel content remains sharp and fully opaque. Popover interactions do not dismiss the panel. Actions that must finish before dismissal set `busy`.
- Adding a control source uses a configuration panel followed by a connection-details panel. The form collects the provider, required provider credentials, required domain for custom and all fixed-domain providers (without a protocol, port, or path), authentication method, and tool policy. The form never asks for an MCP URL; HTTPS and the /mcp path are added automatically for configured domains. It saves without first acquiring a managed URL. After saving, the details panel starts the saved connection and displays its current MCP URL and authentication information. Connection failures remain visible there with a retry action; the saved configuration remains editable.
- Bearer tokens are generated when saving a new Bearer configuration. Existing tokens stay unchanged unless regenerated from connection details. Connection details read credentials through the authenticated, ingress-specific local endpoint and render masked, copyable fields; credentials never enter global status or logs. Secure Tunnel details show Tunnel ID and the saved Runtime API Key instead of an HTTPS MCP URL.
- Connection details show loading only inside the MCP URL field while obtaining the link, preserving the form height. Authentication credentials have their own masked fields without a separate authentication-type row.
- Connection details place Get again beside MCP URL and Regenerate beside Bearer token. Managed URL refresh restarts its ingress; token regeneration restores a previously running connection and leaves stopped connections stopped.
- Opening an existing connection shows details first; Edit opens the configuration form. Blank stored-secret fields preserve credentials. Managed temporary URLs are shown only while available; fixed configured URLs remain viewable when disconnected. Reverse-proxy targets appear in details for custom and named Cloudflare connections.
- `CopyField` combines the library input and button with clipboard handling. `NTooltip` owns hover/focus overlay positioning.

The overview shows ingress transport connectivity independently of inbound verification. The home graph shows installed, enabled Agents up to the configured limit (4 by default; 4, 6, 8, or 10), plus the permanent More branch. Agent links show availability when installed and enabled, and connected status for live sessions. A permanent bottom branch ends in a More button that expands from the More button into an independent Agents panel with a larger header and adjacent refresh and close icon buttons at the top right; Agents settings are not included in the general settings panel. The panel shows all Agents as draggable cards with an enable switch at the top right. Card logos are vertically centered beside the title and version. Titles link to the official website or project, and uninstalled Agents omit the switch. Cards use a compact title/switch row without a drag handle; arrow keys on a focused card also reorder it. The local saved order drives the eligible home-graph entries; disabled and uninstalled entries remain in management only. Codex starts first in the default order and can be disabled like other installed Agents. Closing restores focus to its trigger. Both sides render logos only, with names and status available on hover or focus. Saving display metadata preserves verification; changing transport identity or authentication invalidates it.

## Styling boundaries

The Behavior settings group includes Click control source: Go to service (default) opens the source's external service, while Connection settings opens that instance's connection details. This preference is stored locally and applies immediately. Connection status markers always open connection details, with an Edit action.

Customize library components through `UiProvider` theme overrides and documented props. Do not patch internal selectors from page styles. `SettingsGroup` and `SettingsRow` arrange content without defining their controls. The overview graph, mascot, and main connection button retain custom product visuals.

`native-controls.css` styles existing custom shell controls and excludes library component subtrees. New standard forms do not use these native styles. `tokens.css` applies to custom shell controls; library control tokens live in `UiProvider`.

Settings load as a separate frontend chunk. Shared panels are available when their entry is activated. Keep appearance, localization, focus, keyboard navigation, validation, and save/readback checks part of UI acceptance; use the existing project checks without adding test cases.

Agent icons gently enlarge on hover. Clicking a home Agent icon opens its headerless detail panel with version and available subscription information; connection-status markers open Agents management. Interactive Agent launching remains a separate native capability, independent of quota details and ingress/task lifecycle.

The default window is an edge-to-edge connection canvas with a lower-left navigation capsule. Tasks, records, and settings expand from that capsule into an inset, independently scrollable sheet. The sheet background, content, and footer animate together from the capsule using transform and opacity; opening and closing do not animate layout dimensions, clipping, blur, or shadows. The panel title slides horizontally out next to its lower-left close button, without a top title bar. Content edges align with the left edge of the close icon strokes, with a short gradient above the footer. Navigation icons converge at the close button during expansion and fan back out on collapse. The close button (or Escape) returns to the still-mounted home canvas; keyboard focus returns to the selected navigation button. Native window dragging and Windows window controls remain available. Reduced-motion preferences disable the expansion animation. Collected platform logos and colored Agent SVGs are preferred; brands without a colored asset retain their original monochrome mark.

Curated control sources are ChatGPT, Claude, Microsoft Copilot, Notion, Slack, Cursor, GitHub Copilot and Raycast, plus Custom. Repeated sources are allowed and default names receive an available numeric suffix. See the [support matrix](control-sources.md) for authentication limits.

The compact add-source grid shows logo and name, without additional badges or caveats. Selecting a logo opens a nested configuration panel from that logo while keeping the source grid underneath. Cancelling returns to the grid; saving closes both panels before showing connection details. IngressDialog and SourceIcon consume the shared preset registry; overview tooltips show instance names. Advanced provider/auth configuration remains available through CLI/Codex. Control-source assets have their own semantic map and may reuse Agent brand artwork.

Agent discovery refreshes silently on mount and at each polling interval. Only a manual refresh changes the refresh button and control loading states; concurrent refresh requests share one request.

Capsule panels are anchored at the lower-left entry and default to a maximum width of 960px. Elastic panels expand from the clicked entry toward the window center. Their height follows content within the viewport limit; overflowing content scrolls. Opening lasts 480ms and closing lasts 220ms; reduced-motion preferences disable the transition.

Windows uses the system caption buttons for minimize, maximize/restore, and close. The WebView excludes their native bounds so Windows owns painting, pointer input, accessibility, and caption actions. Windows 11 caption colors follow the opaque canvas and use the shared system material in Translucent mode; older Windows versions retain system caption colors. Closing the release window still hides it to the tray.

HTTPS connections can use OAuth. Clients register dynamically or use a locally registered client ID. An authorization request displays a confirmation code in the browser; the connection-details panel shows pending authorization requests. Each pending request appears as a card below the OAuth heading, with the client name, callback domain, and a danger-styled Deny button. The eight-cell code input supports pasting and automatically approves a complete matching code. Client names are self-reported. Approved cards remain in a loading state until the client exchanges its authorization code and the grant is read back. Connection details list grants with individual revocation; a help icon beside the OAuth heading shows setup instructions in a tooltip. OAuth authorizes the connection's allowed tools and shared tasks, not an isolated user workspace.

Application updates are checked every hour while automatic checking is enabled. About includes an Automatically download updates switch, enabled by default. Automatic downloads verify the package before showing the update dialog or the success-colored update button at the top of the navigation capsule. Turning automatic downloading off shows available updates before downloading. The capsule button starts installation directly; after restarting into that version, its release notes appear once. Downloaded packages are cached for the current app session; downloading never stops connections. Installation restores the previously running connections after restart.

Providers with no temporary-domain support omit the domain-mode field. All providers use the same Fixed domain / Temporary domain labels. Cloudflare fixed domains must be entered by the user; the app does not discover or select domains from remote tunnel routes. Form-label help buttons only respond inside their text bounds; enclosing labels must not implicitly activate those buttons.

## Agent quota and usage presentation

Agents management uses brand names rather than separate CLI product names. Its title-area
settings button opens a secondary settings panel using `SettingsGroup` and `SettingsRow`.
Groups appear in this order: Appearance, Quota, Usage. Appearance controls rail visibility,
size, spacing, and the home Agent count. Quota controls Used/Remaining, reset countdown/date,
and the 1/3/5/10-minute refresh interval. Usage offers Today, Yesterday, Last 7 Days, and
Last 30 Days as independent checkboxes. Rounded rail ends are fixed, not a setting.

Quota details share `QuotaBubble` across the main panel and rail. Plan names link to the
provider's usage page and the refresh icon requests a new reading. Reset counts and usage
periods use left-label/right-value rows. Hovering the value, rather than the whole row,
shows reset-credit expiry dates or model-level token and price estimates. Nested rail
bubbles open horizontally, inherit the parent colors, and share its curved arrow and gap.
Long bubble contents scroll at the outer edge; preserve content during the exit transition.
Model rows place the progress bar above cost and token totals. Consumption-rate warnings
and even-pace ticks use the same logic on both surfaces; see [Subscription usage](subscriptions.md).
