# UI components

The renderer uses React in the existing Tauri system WebView. Rust owns configuration, connections, tasks, authentication, native windows, and updates. Vite builds the main window, tray panel, and usage rail. All three entry points share tokens, preferences, quota presentation, and interaction components.

## Information and navigation

Home is the product-owned connection topology: source and Agent brand nodes, curved status wires, a draggable mascot, and the tactile power switch. Node names and versions appear on demand. The mascot retains state expressions, six click effects, resisted dragging, and damped recoil; its displacement pulls the central ring and attached wires. The power knob springs into place and emits stars on a successful off-to-on transition. The default Agent limit is four; management exposes all discovered Agents.

The lower-left navigation capsule expands into a workspace sheet for Tasks, Records, and Settings. The sheet animates from the capsule, supports a wider layout, and returns focus when closed. Its close control, title, and width control form an ordinary footer inside the content layer and appear with the rest of the content. Task documents use a masonry grid with prompt previews; selecting a document expands it into an elastic detail panel. Records retain filtering and search. Long content scrolls inside sheets and panels.

Configuration, connection details, Agent management, quota details, and updates use ElasticPanel through the shared Dialog export. Panels inherit the clicked anchor’s surface, including its background, border, corner radii, and shadow, then morph into the panel. A temporary inert visual copy keeps anchor content at its original screen position and size, fading it out on expansion and back in on dismissal. The copy remains until the real anchor is restored. The inner content keeps its destination position and size independently of the morphing shell, which clips it during opening and dismissal. Content stays stationary while fading, and navigation sheets use the same separation. Opening paints the captured anchor dimensions before starting the animation clock; the navigation capsule copy reuses its own component styles to keep click preparation short. Opening and dismissal use a smooth, non-spring transition from and to the anchor; position and dimensions progress together, while icons and text keep their original proportions. Source brand icons can designate an inner visual with `data-panel-visual`; navigation uses the whole capsule. Panels can be dragged by their headers and animate content height changes. Navigation inside an open panel transitions from the entire current surface to the next content and size, rather than expanding the clicked control. Each view records its depth; Close, Escape, and outside clicks return one level until the root view dismisses to its original anchor. Previous views retain their form and scroll state. Source selection and configuration are successive steps in the same panel. Clicking another exposed topology or navigation anchor transfers between panels. Tooltips expose runtime values and data-specific details, not fixed action labels; quota details use the product's shared spring-following second bubble.

These layouts, animations, and trigger rules belong to the product. Component-library changes preserve them; Radix supplies interaction primitives, not replacement product styling. Motion drives panel and navigation-shell transitions, continuous highlights, quota bubbles, and rail geometry. Shells animate real dimensions while their content keeps its destination layout; geometry snapshots keep SVG contours and native hit regions in sync. Highlights bind Motion values directly to their decorative layer. Panel and navigation shells share one monotonic easing curve for position, dimensions, and corners, avoiding overshoot or mismatched edge motion. Targets can change during motion without restarting from the original position, and reduced-motion preferences settle geometry immediately.

## Tokens, typography, and icons

`ui/tokens.css` owns semantic canvas, surface, text, border, accent, success, warning, danger, focus, shadow, spacing, radius, and sizing tokens. `ui/style.css` styles standard components; `ui/product.css` owns the topology, mascot, navigation, task documents, and elastic panels. `ui/subscriptions/bubble.css` owns quota bubbles. Do not create page-specific versions of standard controls or patch library internals.

`ui/theme.ts` defaults to system appearance and observes browser and native changes. Explicit Light and Dark choices override it. The first-paint script applies the stored/system choice before rendering. The canvas is opaque white in light mode and black in dark mode; surfaces and borders establish hierarchy. Theme-color swatches update accents independently of semantic warnings and brand artwork.

Typography uses the operating system stack: system UI, Apple system, Segoe UI, PingFang SC, and Microsoft YaHei fallbacks. No proprietary font is bundled. Check actual rendered fonts in the target WebView rather than assuming the first declared family was used. Normal text is 13–14px; metadata uses 12px. Long reading content uses 14px with a relaxed line height. Standard controls are 36px high; compact icon controls are 32px. Spacing follows 4, 8, 12, 16, 24, and 32px steps. Control, row, and panel radii are centralized.

Functional icons use the shared Icon wrapper with Lucide at 16px or 20px and a 1.75px stroke. Icon-only buttons need accessible names; decorative SVGs are hidden from assistive technology. Brand marks retain their original assets and colors.

## Shared controls and floating content

`ui/components/ui/index.tsx` provides Button, IconButton, Input, Field, SingleChoice, Switch, Checkbox, Dialog, StandardDialog, Tooltip, Popover, Menu, Progress, Notice, Status, CopyField, DataTable, Pagination, ErrorCallout, and LoadingIndicator. Group and Row only arrange content. DataTable uses Radix Themes Table with shared semantic tokens. Pagination uses shared buttons and localized navigation labels; page-size choices remain disabled. Simple controls use semantic HTML; Radix supplies selection, focus, keyboard navigation, dismissal, portal positioning, and modal behavior.

- Every single-choice field uses SingleChoice. At most five options render as capsule radios when they fit; larger sets or insufficient width use Radix Select. Theme colors use circular radio swatches. Preserve arrow-key navigation, labels, and disabled states.
- Forms have labels above inputs and one column by default. Field errors connect through `aria-describedby` and `aria-invalid`; invalid submission focuses the first invalid input. Errors do not close forms. Compact controls do not bypass validation.
- Dialogs have an accessible title, scrollable body, and optional header and footer. Radix traps focus and keeps covered content inert. Escape closes only the topmost dialog; focus returns to its trigger. Busy operations can block dismissal.
- Tooltips with additional data appear on hover and focus. Icon buttons retain accessible names without automatic tooltips; navigation and single-choice labels do not add native title hints. Detail popovers also open by keyboard or click, remain interactive, and stay inside viewport bounds. One shared quota detail bubble moves and resizes with a spring when the selected entry changes. It opens after 120 ms on first hover and retains a 180 ms leave corridor. History details trigger on the right-hand values in home, tray, and rail; adjacent history values have contiguous vertical hit areas. The active detail value stays highlighted, including in non-key native rail windows. Rail details use the primary card’s horizontal bounds when flipping sides, keeping the secondary bubble clear of the primary card while following the selected value vertically. Quota estimates open from the pace text, rather than the progress bar or whole reading. Nested quota bubbles report their rounded card outlines for native input hit testing throughout motion.
- Loading, empty, error, disabled, stale, and success states reflect native responses. Cached readings are marked stale after failure. Do not fabricate missing values or silently replace errors with success.

## Continuous highlights

`HoverScope`, exported by the shared UI module, owns one decorative background per related control group. Targets opt in with a unique `data-hover-target`; the interaction owner can supply `activeKey` for retained or native forwarded hover. Without a controlled key, ordinary groups follow pointer and keyboard focus; `tracking="highlighted"` follows Radix `data-highlighted` state without changing its selection or focus behavior. Groups never share a moving background across cards, panels, or windows. Only neutral controls opt in; selection, danger, and primary action styles retain their own meaning. Current targets use a uniform circular corner radius.

History values and reset counts share this background in home, tray, and rail. The home navigation capsule, shared React menus, and SingleChoice dropdown lists also use continuous highlights. Disabled targets are excluded; dangerous menu actions retain their independent feedback. Radio capsules, color swatches, selected-option checkmarks, and native system menus retain their existing presentation. The highlight responds immediately, moves and resizes using the shared spring (response 0.22, damping 0.9), and retargets from its current velocity. First entry places it at the target before fading in; inactive groups retain it for 80 ms before a 100 ms fade. An open detail bubble keeps its source highlighted while the pointer crosses into the detail. Bubble opening and dismissal retain their own timing.

The layer uses the semantic hover token, does not receive pointer events, and never scales text or changes layout. Coordinates remain local to the group during panel transforms; resize, scrolling within the group, and target removal update the geometry. All renderer windows suppress CSS outlines, including pointer and keyboard focus. Focus behavior and restoration remain intact; color selection uses checkmarks, and drag targets use border color. Reduced motion snaps geometry and disables fading.

## Connections and Agents

The add-source picker uses the bundled source registry and allows repeated sources with unique default names. Selecting a source opens its form. Applicable provider, domain, credential, authentication, and tool-policy fields are visible without collapsed validation areas. Field help links sit beside labels. Configured domains omit protocol, port, and path; the service builds the MCP URL. The form saves configuration before connection details start the ingress and display its current result. Failure leaves the saved source editable and offers retry.

Opening a source shows details first; Edit opens configuration. Blank stored-secret inputs preserve credentials. Secrets are read from the authenticated ingress-specific endpoint and displayed as masked, copyable fields; they never enter global status or logs. URL refresh and token regeneration retain native lifecycle behavior. Secure Tunnel shows Tunnel ID and Runtime API Key. Fixed domains and reverse-proxy targets remain readable while stopped.

Tool policy stays compact: preset, count, and View all. A nested dialog lists tools or stages custom checkbox selection; required dependencies stay selected. OAuth details list pending clients and grants with explicit Allow, Deny, and Revoke. Waiting and expired requests follow service state. Client names are self-reported; authorization retains existing connection and task boundaries.

Agent management shows availability, installation/version details, enable switches, and official links. Enabled Agents support drag ordering and arrow-key ordering on focused cards. Discovery refreshes silently unless manually requested. Display settings control rail visibility, size, spacing, home Agent count, quota display, reset time format, refresh interval, and history periods.

## Quota, tray, and native surfaces

On macOS the menu-bar WebView is hosted by a nonactivating NSPanel. It can receive keyboard focus without activating the application and cannot become the main window. Clicking outside the panel or its visible content dismisses it without opening the main window; explicit navigation actions open the main window. Native outside-click monitors preserve the menu-bar icon's toggle and the options menu's tracking session. On Windows, left-clicking the tray icon opens the main window; right-clicking opens a native menu with connection status, Open, Tasks, Records, Settings and Quit. No tray WebView is created on Windows.

QuotaBubble and QuotaRing share presentation across home details, tray, and rail. Summaries show allowance and reset time; model estimates, reset-credit details, and history appear on demand. Unknown amounts remain unknown. Existing pace/cycle calculations and source limitations remain in [Subscription usage](subscriptions.md).

The React rail retains the native layout, pointer, docking, and geometry contract. The browser preview uses the same renderer. Native window placement and OS context menus remain owned by Rust. Nested popovers report bounds for native hit testing. Main-window scrolling is independent of transparent tray/rail constraints.

Update checks, downloads, installation, and release notes retain the native updater. Downloading does not stop connections; installation restores previously running connections. Windows caption controls and macOS integration remain native.

## Responsive behavior and acceptance

Narrow layouts reduce topology geometry while retaining the graph, stack settings controls, wrap actions, and constrain dialogs to the viewport. Dense quota content scrolls inside its available space. Long labels and content wrap without hiding main-page overflow. Reduced-motion preferences disable nonessential animation while retaining state changes.

Validate real loading, empty, connected, unavailable, stale, and error states; keyboard traversal, nested Escape, focus restoration, form errors, theme changes, long localized text, and narrow layouts. Verify native WebView, tray, and rail behavior separately from previews. Use existing checks and real interaction acceptance without adding test cases.

The native rail uses a stable screen-sized canvas while expanded and crops the window only while collapsing. Painted primary and secondary surfaces define mouse input regions independently of the larger hover-retention area and corridors; transparent space passes clicks and scrolling to underlying applications.

## Plugin usage panels

The MCP Apps overview combines the shared QuotaBubble account card with a four-cell summary of tokens, observed requests, estimated cost and input cache hit rate. Shared StackedBarChart (Recharts) renders model-stacked trends for tokens, estimated cost or requests, with a matching model ranking and categorical colors from ui/tokens.css. Today starts at device-local midnight and uses hourly buckets; 7-day and 30-day ranges are rolling and use local dates. Empty buckets retain their position. The searchable task table uses ten rows per page, ordered by latest event first independently of the selected range. Quota and local token measurements retain separate scopes.

The task panel presents a continuous chronological trajectory grouped by turn. The nine summary cells remain visible above the trajectory. A compact turn navigator shows first/last observed context occupancy. A continuous vertical axis joins numbered turn nodes; indented branches connect request, tool and compression nodes. Turn headers use prompt previews with image/annotation counts; a Prompt label opens full text in a compact popover. Only expanded turns load their calls. All turn headers are rendered at once. Expanding a turn loads and displays every request, tool call and compression event without intermediate load-more controls. The navigator previews turn summaries on hover or focus and scrolls to the expanded turn on activation. Shared HoverPreviewGroup keeps one Radix preview mounted across adjacent targets, animates its position and content height, and reuses HoverScope for the moving background. Initial hover is delayed, movement between targets is immediate, and Escape or outside scrolling dismisses the preview; reduced motion disables transitions. Request rows preview associated assistant output, falling back to a tool operation excerpt; their inspector includes the full recorded assistant text alongside context and usage. Assistant messages are associated with the next same-turn usage record without crossing compression boundaries; logs do not provide a direct message-to-request ID or a complete outbound request body. Tools are grouped with a request when their emission-to-completion interval contains exactly one reliable response in the same turn without an intervening compression event. One request can contain multiple tools; ambiguous and unfinished calls remain separate. Grouping preserves request token/cost totals and tool byte totals independently. Tool calls show duration, output size, status and cumulative output size; their Details dialog loads the original input and output on demand. Timeline rows omit expansion chevrons and selected-edge accents. Shared Motion size transitions animate disclosures, prompt header height and dialog content changes without scaling text; Radix owns disclosure and dialog accessibility. Closing content is inert, and reduced-motion preferences disable size transitions. Turns with compression use amber number markers. Plaintext reasoning summaries are included in the next same-turn request inspector when no compression boundary intervenes; they do not add timeline nodes. Consecutive identical summaries within a request are combined with their count, time range and recorded duration. They are read on demand for the expanded turn and deduplicated by item ID; empty summaries and encrypted payloads are omitted. Compression rows are static, with event time and duration when explicit lifecycle timestamps are recorded. There is no turn detail modal. Request input tokens, including cached input, are context observations, not cumulative billed tokens. Recorded model context capacity defines occupancy; missing observations remain unknown. Compression comparisons use adjacent request observations and may include subsequent new content. Tool bytes are not context tokens, and subsequent request changes cannot be attributed to a single tool. Usage shows per-call and within-turn cumulative tokens/cost, marking partial totals. Task-wide response and tool lists remain available through Overview. Task selection affects only the current panel.

Loading and indexing states show only a centered Radix Spinner with an accessible status label. Fetch failures use the shared Radix Callout with a separate retry action, preserving any ready snapshot. Primary surfaces use short labels and data. Explanations and provenance live behind information controls, tooltips, and secondary panels. HoverScope provides continuous row feedback; Motion animates transitions and record expansion, with reduced-motion support. Shared controls, semantic colors, host appearance and locale, keyboard dismissal, and focus restoration apply to both panels.
