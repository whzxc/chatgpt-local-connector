# UI components

The Vue desktop frontend uses Naive UI for standard controls. Import components by name rather than registering the entire library. `UiProvider` owns shared typography, control sizes, corner radii, brand colors, dark mode, and the English/Chinese component locale. `theme.ts` owns reactive appearance and theme-color preferences. General settings place five circular color swatches immediately below Appearance: Forest (default), Ocean, Violet, Amber, and Rose. The locally persisted selection updates control accents and the canvas in both light and dark modes. Translucent is a separate, locally persisted switch below the theme colors, disabled by default. It reveals the native macOS Sidebar or Windows Acrylic material through a tinted translucent canvas; turning it off restores an opaque canvas. Panels remain opaque for readability. Browser previews show the translucent styling but cannot blur the desktop behind the browser.

## Forms and panels

- Use `NForm` and `NFormItem`, with labels above inputs and one column by default. Listener addresses and ports are managed by the application; show a copyable reverse-proxy target when needed, not editable fields.
- Use `NInput`, `NInputNumber`, `SingleChoice`, `NSwitch`, and `NButton` for standard controls. Supply accessible input names.
- Put credential and provider help links on the right of the field label, on the same line. Show the selected platform in the dialog title; the editable display name remains a form field. Platform selection uses the bundled brand icons, with a dashed plus for custom sources.
- All single-choice fields use `SingleChoice`: up to four options render as capsule tabs; larger sets render as a dropdown, except the theme-color selector, which uses five circular swatches. Radio colors and capsule radii belong to `UiProvider`. Preserve accessible labels, keyboard navigation, disabled states, and form validation.
- Alerts and banners omit leading icons. ChatGPT shows a Secure Tunnel recommendation tag with a hover explanation instead of a preset banner. HTTPS-only sources omit the transport selector and include HTTPS MCP in the provider label.
- The final connection field is Tool list (工具列表): All / Common / Read-only / Custom. The field stays compact in every mode, showing a tool count and View all. A nested ElasticPanel lists preset tools or provides grouped Naive UI checkboxes for Custom, with Done/Cancel staging selection in the connection form; required verification and reader dependencies remain selected. The authenticated management catalog is independent of ingress discovery filters.
- Keep validation next to its field. Connection dialogs render every applicable field directly, without collapsed sections. Errors do not submit or close the form.
- Use `ElasticPanel` for control-source configuration, connection details, Agents, tool lists, task details, and application updates. Panels expand from the clicked trigger toward the window center, with content-driven height, viewport-constrained maximum dimensions, scrollable content, and an optional footer. The shared panel has no width toggle. Width and content-driven height changes transition smoothly over 320ms while preserving window-centered positioning; reduced-motion preferences disable this transition. Clicking outside or pressing Escape closes only the topmost panel with the collapse transition and restores focus to its trigger. Parent panels and workspace controls remain inert until the topmost panel finishes closing. Layered shadows distinguish the active panel; covered panels soften their shadows, then smoothly restore when uncovered. Panel content remains sharp and fully opaque. Popover interactions do not dismiss the panel. Actions that must finish before dismissal set `busy`.
- Adding a control source uses a configuration panel followed by a connection-details panel. The form collects the provider, required provider credentials, optional fixed Cloudflare domain, required custom or ngrok fixed domain (without a protocol, port, or path), authentication method, and tool policy. The form never asks for an MCP URL; HTTPS and the /mcp path are added automatically for configured domains. It saves without first acquiring a managed URL. After saving, the details panel starts the saved connection and displays its current MCP URL and authentication information. Connection failures remain visible there with a retry action; the saved configuration remains editable.
- Bearer tokens are generated when saving a new Bearer configuration. Existing tokens stay unchanged unless regenerated from connection details. Connection details read credentials through the authenticated, ingress-specific local endpoint and render masked, copyable fields; credentials never enter global status or logs. Secure Tunnel details show Tunnel ID and the saved Runtime API Key instead of an HTTPS MCP URL.
- Connection details show loading only inside the MCP URL field while obtaining the link, preserving the form height. Authentication credentials have their own masked fields without a separate authentication-type row.
- Connection details place Get again beside MCP URL and Regenerate beside Bearer token. Managed URL refresh restarts its ingress; token regeneration restores a previously running connection and leaves stopped connections stopped.
- Opening an existing connection shows details first; Edit opens the configuration form. Blank stored-secret fields preserve credentials. Managed temporary URLs are shown only while available; fixed configured URLs remain viewable when disconnected. Reverse-proxy targets appear in details for custom and named Cloudflare connections.
- `CopyField` combines the library input and button with clipboard handling. `NTooltip` owns hover/focus overlay positioning.

The overview shows ingress transport connectivity independently of inbound verification. The home graph shows at most four Agents plus the permanent More branch. Agent links show availability when installed and enabled, and connected status for live sessions. A permanent bottom branch ends in a More button that expands from the More button into an independent Agents panel with a larger header and adjacent refresh and close icon buttons at the top right; Agents settings are not included in the general settings panel. The panel shows all Agents as draggable cards with an enable switch at the top right. Card logos are vertically centered beside the title and version. Titles link to the official website or project, and uninstalled Agents omit the switch. Cards use a compact title/switch row without a drag handle; arrow keys on a focused card also reorder it. The local saved order drives the first four home-graph entries, including disabled or unavailable entries. Codex starts first in the default order and can be disabled like other installed Agents. Closing restores focus to its trigger. Both sides render logos only, with names and status available on hover or focus. Saving display metadata preserves verification; changing transport identity or authentication invalidates it.

## Styling boundaries

The Behavior settings group includes Click control source: Go to service (default) opens the source's external service, while Connection settings opens that instance's connection details. This preference is stored locally and applies immediately. Connection status markers always open connection details, with an Edit action.

Customize library components through `UiProvider` theme overrides and documented props. Do not patch internal selectors from page styles. `SettingsGroup` and `SettingsRow` arrange content without defining their controls. The overview graph, mascot, and main connection button retain custom product visuals.

`native-controls.css` styles existing custom shell controls and excludes library component subtrees. New standard forms do not use these native styles. `tokens.css` applies to custom shell controls; library control tokens live in `UiProvider`.

Settings load as a separate frontend chunk. Shared panels are available when their entry is activated. Keep appearance, localization, focus, keyboard navigation, validation, and save/readback checks part of UI acceptance; use the existing project checks without adding test cases.

Agent icons gently enlarge on hover. Clicking Codex opens its desktop application; CLI icons open their interactive executable in a user-owned terminal, without ACP/RPC arguments. On macOS, the system handler for executable `.command` files selects the terminal; on Windows, a new PowerShell console uses the configured console host. Interactive launches start in the home directory and are independent of ingress/task lifecycle.

The default window is an edge-to-edge connection canvas with a lower-left navigation capsule. Tasks, records, and settings expand from that capsule into an inset, independently scrollable sheet. A single surface keeps the same background while growing from the capsule and shrinking back. The panel title slides horizontally out next to its lower-left close button, without a top title bar. Content edges align with the left edge of the close icon strokes, with a short softened transition above the footer. Navigation icons converge at the close button during expansion and fan back out on collapse. The close button (or Escape) returns to the still-mounted home canvas; keyboard focus returns to the selected navigation button. Native window dragging and Windows window controls remain available. Reduced-motion preferences disable the expansion animation. Collected platform logos and colored Agent SVGs are preferred; brands without a colored asset retain their original monochrome mark.

Curated control sources are ChatGPT, Claude, Microsoft Copilot, Notion, Slack, Cursor, GitHub Copilot and Raycast, plus Custom. Repeated sources are allowed and default names receive an available numeric suffix. See the [support matrix](control-sources.md) for authentication limits.

The compact add-source grid shows logo and name, without additional badges or caveats. Selecting a logo opens a nested configuration panel from that logo while keeping the source grid underneath. Cancelling returns to the grid; saving closes both panels before showing connection details. IngressDialog and SourceIcon consume the shared preset registry; overview tooltips show instance names. Advanced provider/auth configuration remains available through CLI/Codex. Control-source assets have their own semantic map and may reuse Agent brand artwork.

Agent discovery refreshes silently on mount and at each polling interval. Only a manual refresh changes the refresh button and control loading states; concurrent refresh requests share one request.

Capsule panels are anchored at the lower-left entry and default to a maximum width of 960px. Elastic panels expand from the clicked entry toward the window center. Their height follows content within the viewport limit; overflowing content scrolls. Opening lasts 480ms and closing lasts 220ms; reduced-motion preferences disable the transition.
